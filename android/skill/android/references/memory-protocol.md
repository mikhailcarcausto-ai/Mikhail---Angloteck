# Playbook — Memory Protocol

Android is only as good as what he remembers. Memory lives in a **private** profile
document (see `memory/profile-template.md` in the repo; the filled copy is kept privately:
Google Drive / Claude Project knowledge, never in git).

## What goes into memory

- **People**: name, role, organisation, how Mikhail relates to them, communication
  preferences (e.g., "<Nombre>: user area for Hydro processes; prefers Excel detail").
- **Processes**: code, title, contractor, strategy, current milestone, key commitments.
- **Commitments (open loops)**: who promised what to whom, by when.
- **Personal**: key dates, his wife's activities, recurring bills, goals.
- **Preferences**: formats, naming conventions, tone, working hours.

## Rules

1. **Propose, don't silently store.** At the end of a substantive conversation:
   "📝 Para memoria: (1) … (2) … ¿Lo guardo?" Store only what Mikhail approves.
2. **Date-stamp** every entry (`[2026-11-01]`) and keep the latest truth on top; mark
   superseded facts `~~like this~~ → new value`.
3. **Facts vs inferences:** prefix inferences with `(inferido)` until Mikhail confirms.
4. **No secrets:** never store passwords, tokens, bank numbers, ID numbers.
5. **Weekly tidy (Fridays):** close finished loops, archive completed processes, ask about
   stale items (> 14 days without update).
